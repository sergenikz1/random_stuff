# Intergalactic TV — видео из интернета на телевизоре

Android TV приложение с поиском по сайтам, встроенным браузером и плеером Media3.
Для онлайн-просмотра сервер не нужен. Дополнительно можно подключить домашний
медиаменеджер [Scryer](https://github.com/scryer-media/scryer), управлять библиотекой
и загрузками с пульта.

Проект находится в `intergalactic-tv/` и не связан с остальными приложениями репозитория.

## Поиск по сайтам (1.4)

1. Откройте «Найти онлайн» и введите название с клавиатуры или голосом.
2. В интерфейсе остаётся введённое название. В запрос к поисковику приложение
   незаметно добавляет **«смотреть онлайн»**: `Солярис` → `Солярис смотреть онлайн`.
3. Первые **шесть разных ссылок** проверяются параллельно. Приложение ищет
   `<video>/<source>`, Open Graph и JSON-LD VideoObject. Карточки сохраняют
   порядок выдачи и показывают название, сайт и доступную обложку.
4. Нажмите «Смотреть»: страница откроется во встроенном ТВ-браузере. Кнопки
   «▶ / Ⅱ», «−10 с», «+10 с», «Видео крупно» управляют HTML5-видео.
   «К сайту» возвращает исходный вид страницы.
5. Для элементов сайта используйте стрелки/OK. «Курсор» включает указатель:
   стрелки двигают его, OK нажимает. **Menu** возвращает фокус к кнопкам приложения.
6. После запуска видео «В ТВ-плеере» позволяет выбрать обнаруженный поток и
   воспроизвести его в Media3. Поддерживаются также HLS/DASH-запросы динамических
   плееров; исходная страница остаётся в истории для повторного открытия.

Используется DuckDuckGo HTML, при ошибке или проверке на бота — Bing.
Если сайт не отвечает, его карточка остаётся доступна для открытия в браузере.
Если поисковик требует проверку или не вернул ссылки, полка предлагает «Поиск
в браузере». Rutube и добавленные пользователем источники ищутся независимо.
«Открыть ссылку» принимает обычные веб-страницы наряду с прямыми потоками.

Плееры в чужом iframe могут требовать собственные кнопки: приложение не может
управлять их DOM через границу origin. Для них доступны «Видео крупно», курсор
и штатный полноэкранный режим сайта. DRM, вход, региональные ограничения и
совместимость сайта с Android System WebView определяются самим сервисом.
Извлечение прямого потока возможно не у каждого сайта; страница или обнаруженный
поток могут оказаться недоступны. Качество и автопереход Media3 не управляют
плеером внутри сайта. Позицию Media3 приложение сохраняет, браузерную позицию
может сохранять сам сайт. При уходе из браузера страница выгружается, чтобы
звук iframe не продолжал играть в фоне; при возврате она загружается заново.

У браузера нет JavaScript-моста в Android, доступа к файлам и content URI,
внешним intent-ссылкам и всплывающим окнам. Ошибки TLS не игнорируются.
Сторонние cookies и смешанное HTTP-содержимое HTTPS-страниц отключены.
Для нативного просмотра cookies берутся из браузера отдельно для каждого
адреса, включая редиректы; они не записываются в карточки истории.
Ключ Scryer не передаётся поисковику, сайтам и плееру.

## Переименование и обновление

Название, исходники, ресурсы, каталог, APK и workflow переименованы в
**Intergalactic TV**. Android `applicationId = org.scryertv.client`, файл старых
настроек, постоянный сертификат и переменные `SCRYERTV_*` намеренно сохранены:
с прежним ключом подписи новая версия обновляет установленное приложение,
сохраняя историю, избранное и настройки. Kotlin namespace теперь
`org.intergalactictv.client`. Версия — **1.4.0**, versionCode — **6**.
Новые релизы используют `intergalactic-tv-*`; установленную старую версию
можно обновить новым подписанным APK вручную.

## Что умеет

- **Главный экран** в стиле Android TV (leanback):
  - «Загрузки» — очередь с прогрессом, обновляется каждые 10 секунд;
  - «Скоро выйдет» — календарь серий на две недели вперёд (есть / ждём);
  - «Новое в фильмах / сериалах / аниме» — последние добавленные тайтлы;
  - подборки «Обзора» Scryer (персональные и общие рекомендации);
  - меню: поиск, вся библиотека по разделам, очередь, настройки.
- **Поиск** (в том числе голосовой) сразу в своей библиотеке и в базе
  метаданных Scryer: фильмы, сериалы и аниме отдельными полками.
- **Карточка тайтла**: постер, фон, описание, рейтинг, качество, сколько серий есть.
  - Не в библиотеке — «Добавить и скачать» (для сериалов: все серии или только новые).
    Scryer сам найдёт и скачает релиз. Если у пользователя нет права добавлять,
    уходит запрос на одобрение администратору.
  - В библиотеке — «Найти и скачать» (лучший релиз сейчас), включить/выключить
    отслеживание, «Смотреть» — открыть тайтл в Plex/Jellyfin/Emby, если сервер
    медиатеки подключён к Scryer.
  - Полка «Похожее».
- **Библиотека** сеткой постеров по разделам, с подгрузкой при прокрутке.
- **Очередь загрузок** отдельным экраном, обновляется каждые 5 секунд.

## Онлайн-просмотр (1.1)

Встроенный плеер Media3 играет видео без предварительной загрузки файла.
При первом запуске можно сразу смотреть онлайн, не подключая сервер Scryer.
После подключения сервера раздел доступен через «Смотреть онлайн» в главном меню,
в карточке фильма/сериала и на экране ошибки подключения.

- **Rutube:** поиск по названию с подгрузкой результатов, открытие ссылки на видео.
  Клиент использует только контентный поток из API, без рекламного веб-плеера.
- **Сериалы:** «Серии и сезоны» показывает нумерованные серии одного сериала от
  одного автора. Распознаются `S01E02`, `1 сезон 2 серия`, `серия 2`.
  В конце серии включается следующий номер, затем первый эпизод следующего сезона.
  Пропуск номера или неизвестная нумерация останавливают автоматическую очередь.
  Поиск ограничен первыми восемью страницами результатов Rutube.
- **Свои источники** (меню «Источники»): пользователь сам добавляет, включает,
  обновляет и удаляет источники. Кроме Rutube и поиска по сайтам, используются источники пользователя.
  - *M3U-плейлисты* — группы плейлиста становятся полками главного экрана.
  - *Дополнения в открытом формате Stremio* — ссылка на `manifest.json`
    (или `stremio://…`). Их каталоги становятся полками, каталоги с поиском
    участвуют в онлайн-поиске, у сериалов есть список сезонов и серий.
  - При нажатии «Смотреть» приложение собирает ссылки на это видео со всех
    включённых источников и спрашивает, **откуда смотреть** (источник, качество,
    озвучка). Для фильма из плейлиста предлагаются и одноимённые видео из других
    плейлистов. Следующая серия при автопереходе берётся у того же источника
    с той же озвучкой (`bingeGroup` или та же подпись ссылки).
  - Воспроизводятся только ссылки HTTP/HTTPS. Торренты (`infoHash`), YouTube и
    внешние ссылки пропускаются. Заголовки, которых требует источник
    (`behaviorHints.proxyHeaders`, например Referer), передаются плееру.
  - За содержимое источников отвечает тот, кто их добавил: добавляйте только
    источники, которыми вам разрешено пользоваться.
- **M3U:** «Открыть ссылку» импортирует плейлист до 200 видео / 2 МБ и сохраняет его как источник. Серии
  проигрываются в порядке файла внутри `group-title`; разные сериалы стоит
  поместить в разные группы. HLS-манифест `.m3u8` считается одним видео, а его
  сегменты никогда не превращаются в отдельные серии.
- **Прямые ссылки:** HTTP/HTTPS MP4, MKV, WebM, HLS и DASH, без веб-страниц.
- Позиция сохраняется каждые пять секунд и при выходе, есть история и избранное.
  Плеер поддерживает пульт, паузу, перемотку ±10 секунд, аудиофокус и выбор
  максимального качества. В фоне воспроизведение останавливается.
- За минуту до конца запрашивается адрес следующей серии; за 20 секунд появляется
  кнопка перехода с возможностью отменить автопереход. Настройка автоперехода
  сохраняется в «Настройках плеера».

Пример M3U для собственного каталога:

```m3u
#EXTM3U
#EXTINF:-1 group-title="Сериал",Сезон 1 · Серия 1
https://media.example.org/series/s01e01.mp4
#EXTINF:-1 group-title="Сериал",Сезон 1 · Серия 2
https://media.example.org/series/s01e02.m3u8
```

Поиск по сайтам и Rutube работает без добавления источников. Каталоги дополнений
и M3U остаются отдельными источниками. Реклама и ограничения самого сайта
не удаляются. Доступность сервисов зависит от региона и сети.

Просмотр скачанной библиотеки Scryer по-прежнему открывает Plex/Jellyfin/Emby.
Ключ доступа Scryer не передаётся онлайн-источникам: у них отдельный HTTP-клиент.

## Подключение к серверу

При первом запуске можно выбрать онлайн-просмотр. Для подключения библиотеки укажите адрес Scryer — тот же, что в браузере,
например `http://192.168.1.10:8080` (если Scryer за обратным прокси с путём —
вместе с путём: `https://home.example.com/scryer`). Дальше один из трёх способов:

1. **Логин и пароль** (и код 2FA, если включён). Приложение входит и выпускает
   себе бессрочный API-ключ «Intergalactic TV», пароль не сохраняется. Если сервер не дал
   выпустить ключ (например, просит свежее подтверждение 2FA), приложение работает
   на обычной сессии — когда она истечёт, попросит войти снова.
2. **Без пароля** — если вход в Scryer выключен или включён обход для локальной сети.
3. **Готовый API-ключ** (`ska_…`) из веб-интерфейса: Настройки → Безопасность → API-ключи.

Отозвать доступ телевизора — удалить ключ «Intergalactic TV» в веб-интерфейсе.
«Настройки → Сменить сервер или выйти» в приложении стирает ключ с телевизора.

Проверено по схеме GraphQL Scryer **v0.21.20** (`api/graphql/schema.graphql`).

## Сборка

### Через GitHub Actions (ничего ставить не нужно)

Workflow `.github/workflows/intergalactic-tv.yml` собирает APK на каждый push в
каталог `intergalactic-tv/`. Свежий APK из ветки `main` лежит в предрелизе
**`intergalactic-tv-latest`** (раздел Releases), а также в артефактах запуска
(`IntergalacticTV-apk`): **Actions → нужный запуск → Artifacts**.

Запустить вручную: **Actions → Intergalactic TV — сборка APK → Run workflow**.

Для отдельной тестовой версии отправьте тег `intergalactic-tv-v<версия>`:
при настроенном постоянном ключе workflow проверит тесты, соберёт APK и
опубликует prerelease с контрольной суммой и описанием обновления.
Это позволяет установить новую онлайн-версию до слияния её ветки в `main`.

### Локально

Нужен JDK 17 и Android SDK (`ANDROID_HOME`), сеть до `dl.google.com` и
Maven Central:

```bash
cd intergalactic-tv
./gradlew assembleRelease
# APK: app/build/outputs/apk/release/app-release.apk

# Проверки очереди серий, M3U и сериализации:
./gradlew testDebugUnitTest
```

Без постоянного ключа release-сборка остаётся неподписанной и не публикуется
как обновление. Случайные отладочные ключи для релизов больше не используются.
Для отладки можно собрать `assembleDebug` с отдельным applicationId.

### Подпись релизным ключом

Для релизов используется существующий постоянный ключ, соответствующий
`release-signing-certificate.pem`. Подпись и способы публикации описаны ниже
в разделе «Обновление приложения с пульта». Новый случайный ключ не совместим
с уже установленными версиями.

## Установка на телевизор

1. Скачайте APK из релиза `intergalactic-tv-latest`.
2. Включите на ТВ установку из неизвестных источников.
3. Поставьте любым способом:
   - `adb connect <ip-телевизора>:5555 && adb install -r IntergalacticTV-*.apk`
   - или через файловый менеджер / «Send files to TV» с флешки.
4. Приложение появится в списке приложений Android TV (и в обычном лаунчере —
   `leanback` помечен как необязательный, поэтому ставится и на приставки).

Требования: Android 5.0+ (minSdk 21). Для библиотеки и загрузок нужен сервер
Scryer; онлайн-просмотр и обновление работают без него.

## Структура

```
intergalactic-tv/app/src/main/java/org/intergalactictv/client/
├── data/        ScryerApi (HTTP + авторизация), Queries (все GraphQL-запросы),
│                Repository (сценарии и разбор ответов), модели, Prefs
├── ui/          главный экран, поиск, карточка тайтла, библиотека, очередь,
│                вход, настройки
└── util/        форматирование размеров, дат, статусов
```

Все запросы к Scryer собраны в одном файле — `data/Queries.kt`. Если в новой
версии Scryer поменяется схема, правится только он:

| Что | GraphQL |
| --- | --- |
| Вход | `login`, затем `createMyApiKey` |
| Вход без пароля | `GET /authless-client`, затем `createMyApiKey` |
| Главный экран | `titles(facet, sort: ADDED)` со счётчиком `totalCount` |
| Календарь | `calendarEpisodes(startDate, endDate)` |
| Обзор | `discoveryHome` |
| Поиск | `titles(query)`, `searchMetadataMulti` |
| Карточка | `title(id)` с `playbackLinks` и `moreLikeThis` |
| Очередь | `downloadQueuePage` |
| Добавить | `addTitle`, при нехватке прав — `submitMediaRequest` |
| Скачать | `queueBestRelease(scope: { title: true })` |
| Отслеживание | `setTitleMonitored` |

Запросы проверены валидатором `graphql-js` против схемы Scryer v0.21.20.

## Ограничения

- Настройка Scryer (индексаторы, клиенты загрузки, профили качества, правила)
  остаётся в веб-интерфейсе — с пульта это неудобно.
- Добавление идёт в библиотеку по умолчанию для раздела, с её профилем качества.
- Нет выбора конкретного релиза вручную (интерактивного поиска) — только
  «лучший релиз» по правилам Scryer.
- Приложение неофициальное и не связано с авторами Scryer.


## Обновление приложения с пульта (1.2)

В онлайн-разделе и настройках есть кнопка **«Обновить приложение»**. Она открывает
проверку GitHub Releases только этого проекта, включая preview-версии. Если найден
APK с большим `versionCode`, нажмите **«Скачать и установить»**. Android 8+ при первом
обновлении попросит разрешить установку приложений из Intergalactic TV; после возврата
откроется обычное подтверждение установки Android. Без подтверждения установка
не выполняется. При обновлении история, избранное, подключение к серверу и
настройки сохраняются.

Проверка использует `intergalactic-tv-update.json`, опубликованный вместе с APK.
Изолированный HTTP-клиент работает по HTTPS, не передаёт ключ Scryer и разрешает
перенаправления только на GitHub/CDN GitHub. APK скачивается во внутренний кеш;
проверяются длина, SHA-256, имя пакета, версия и совпадение подписи с установленным
приложением. Перед открытием установщика проверки повторяются. Неполный файл или
файл с чужой подписью не передаётся установщику. Для передачи используется
FileProvider с доступом только на чтение к папке кеша обновлений.

**Переход с 1.1 preview:** старый APK подписан временным ключом GitHub runner.
Для установки первой версии 1.2 с постоянной подписью нужно один раз удалить
старую preview-версию; её локальные настройки при этом сбросятся. Версии 1.2 и
последующие устанавливаются поверх, если сохранять постоянный ключ подписи.

### Постоянная подпись и публикация

Публичный сертификат хранится в `release-signing-certificate.pem`. Для обновления
установленного приложения нужен прежний закрытый ключ и его пароль из защищённого
хранилища владельца. Переименование не меняет ключ и не переносит его файлы.
В репозиторий они не включены; наличие ключа в новой рабочей среде не предполагается.
Не публикуйте ключ и пароль в Git, логах или Releases. APK с новым ключом не обновит
уже установленную версию с прежней подписью.

Локальная сборка и подпись (после каждого изменения увеличивайте `versionCode`):

```sh
./gradlew --no-daemon testDebugUnitTest assembleRelease lintRelease
ANDROID_HOME=/path/to/android-sdk \
SCRYERTV_KEYSTORE_FILE=/secure/intergalactic-tv/release.jks \
SCRYERTV_PASSWORD_FILE=/secure/intergalactic-tv/keystore-password.txt \
bash scripts/sign-release.sh
```

Скрипт проверяет сертификат, package, версию и создаёт `out/IntergalacticTV-<версия>.apk`,
`intergalactic-tv-update.json` и `SHA256SUMS.txt`. Ключи не передаются в аргументах или логах;
пароль читается из защищённого файла.

Для полностью автоматической сборки можно задать GitHub Secrets
`SCRYERTV_KEYSTORE_BASE64`, `SCRYERTV_KEYSTORE_PASSWORD`, `SCRYERTV_KEY_ALIAS=scryertv`,
`SCRYERTV_KEY_PASSWORD` с этим же постоянным ключом. Workflow проверяет соответствие
публичному сертификату перед публикацией. Для тегов `intergalactic-tv-v<version>` создаётся
preview-релиз, для `main` обновляется `intergalactic-tv-latest`.

Если доступ к GitHub Secrets ограничен, поддерживается публикация заранее
подписанного APK, как в проекте Limit Pulse этого репозитория:

1. Соберите и подпишите APK локально скриптом выше.
2. Положите **только готовый APK** под именем `IntergalacticTV.apk` в отдельный временный
   artifact-коммит/ветку и отправьте его на GitHub. Закрытый ключ остаётся локально.
3. Запустите workflow `intergalactic-tv.yml` на ветке с кодом, передав `signed_apk_commit`
   (полный SHA artifact-коммита), `signed_apk_sha256` и `release_tag`, например
   `intergalactic-tv-v1.2.0`. Workflow заново проверит тесты, пакет, версию, SHA-256 и
   постоянный сертификат, затем опубликует APK с метаданными обновления.
4. После успешной публикации удалите временную artifact-ветку. APK доступен в
   Releases и дальше скачивается кнопкой в приложении.

Старые релизы без `intergalactic-tv-update.json` не предлагаются как обновление. Релизы
других проектов, черновики и версии с меньшим/тем же `versionCode` игнорируются.


## Исправления плеера в 1.2.1

- При достижении нуля на плашке следующая серия запускается автоматически, даже
  если HLS-поток не прислал событие окончания или продолжает увеличивать свою
  длительность. Таймер не уходит в минус, останавливается на паузе/буферизации и
  сбрасывается при перемотке. Переключение выполняется один раз.
- Когда плашка видна, ↑ или ↓ переводят фокус с видео на «Включить сейчас».
  Стрелки переключают кнопки, OK нажимает выбранную; ←/→ или «Назад» возвращают
  фокус к видео. «Отменить автопереход» оставляет текущую серию.
- Временные ошибки запуска автоматически повторяются не более двух раз с новым
  адресом потока, сохранением позиции и состояния паузы.
- При `ERROR_CODE_DECODING_FAILED` / ошибке запуска декодера повторный запуск
  предпочитает программный декодер и ограничивает доступное адаптивное качество
  до 720p, при повторной ошибке — до 480p. Этот режим сохраняется для следующих
  серий текущего просмотра. Это не добавляет отсутствующие в Android кодеки и не
  перекодирует прямой MP4-файл: неподдерживаемое видео может остаться недоступным.
- Для HLS явно указывается формат, в том числе для адресов без `.m3u8` в пути.
  Сессионные cookie источника/CDN хранятся в памяти и передаются только подходящим
  хостам. Ключ сервера Scryer по-прежнему не передаётся видеоисточникам.

Проверки включают тесты экрана Android через Robolectric: пульт без мыши,
автоматический переход без `STATE_ENDED`, отмену перехода, восстановление после
сетевой ошибки и `ERROR_CODE_DECODING_FAILED`. Android SDK для тестов скачивается
через Gradle, затем тесты работают с локальными SDK без сетевых запросов.
