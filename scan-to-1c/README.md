# Сканы → 1С

Программа для Windows (`Scan2-1C.exe`): принимает сканы первичных документов, распознаёт текст,
извлекает реквизиты и загружает документы в 1С:Предприятие 8.3.

## Что умеет

- **Форматы:** PDF (с текстовым слоем читается напрямую, сканированный — через OCR), JPG, PNG,
  TIFF (в том числе многостраничные), BMP, GIF, WEBP, HEIC с телефона.
- **OCR:** Tesseract 5 с русским и английским языком встроен в exe, ставить ничего не нужно.
  Перед распознаванием скан выравнивается по EXIF, переводится в оттенки серого, мелкие увеличиваются,
  страницы, отсканированные боком или вверх ногами, разворачиваются.
- **Документы:** счёт на оплату, УПД, счёт-фактура, товарная накладная (ТОРГ-12), акт, платёжное поручение.
- **Реквизиты:** тип, номер, дата; продавец и покупатель (наименование, ИНН, КПП); сумма, ставка и сумма НДС;
  БИК, расчётный и корреспондентский счёт.
- **Проверки:** контрольная сумма ИНН, сходимость НДС со ставкой; исправление типичных ошибок OCR
  (латиница вместо кириллицы, «Ne» вместо «№», «000» вместо «ООО»). Сомнительные документы помечаются «Проверьте».
- **Загрузка в 1С** одним из двух способов:
  1. **Сразу в базу (OData).** Организация находится по ИНН покупателя, контрагент — по ИНН продавца
     (если его нет, создаётся). Документ создаётся **непроведённым**, повторная загрузка того же скана дубль не создаёт.
  2. **В папку обмена.** Для каждого документа кладутся JSON с реквизитами и копия скана; в 1С их забирает
     обработка из [`1c/ЗагрузкаСканов.bsl`](1c/ЗагрузкаСканов.bsl).

## Как пользоваться

1. Скачайте `Scan2-1C.exe` из раздела Releases репозитория (или из артефактов сборки «Сканы → 1С»)
   и положите в любую свою папку, например на Рабочий стол. Дальше программа обновляется сама.
2. Добавьте сканы кнопками «Добавить файлы» / «Добавить папку» или перетащите файлы на значок exe.
3. Нажмите «Распознать». Справа видны найденные реквизиты, на вкладке «Распознанный текст» — весь текст
   (его можно поправить и нажать «Извлечь реквизиты из текста заново»). Двойной щелчок открывает скан.
4. Проверьте и при необходимости исправьте поля, нажмите «Сохранить правки».
5. «Настройки» → укажите адрес базы, пользователя и пароль → «Проверить подключение».
6. «Загрузить в 1С» — загрузятся выделенные документы, а если ничего не выделено — все распознанные.

Распознать без окна, например из планировщика:

```
Scan2-1C.exe --extract скан1.pdf скан2.jpg --out результат.json
```

## Распознавание ИИ через OmniRoute

По умолчанию реквизиты ищутся шаблонами (регулярными выражениями) — это работает офлайн, но только на типовых
формах. С ИИ программа понимает любой макет счёта, акта или УПД. Модели подключаются через
[OmniRoute](https://github.com/diegosouzapw/OmniRoute) — шлюз с одним OpenAI-совместимым адресом
перед множеством провайдеров (OpenAI, Anthropic, Google, бесплатные модели и т. д.).

1. Запустите OmniRoute (`npx omniroute` или `docker run -p 20128:20128 diegosouzapw/omniroute`) и подключите
   в его панели (`http://localhost:20128`) хотя бы одного провайдера с моделью, которая видит изображения.
2. В программе: «Настройки» → «Распознавание ИИ» → включите галочку, адрес `http://localhost:20128/v1`,
   ключ — из панели OmniRoute (Dashboard → Endpoints; если OmniRoute не требует ключ, поле можно оставить пустым),
   модель — `auto`. «Проверить OmniRoute» покажет, сколько моделей доступно.
3. «Распознать» работает как раньше, в строке документа появится «Распознано ИИ (модель)».

Как это устроено:

- Модели отправляются текст после OCR и картинки первых 5 страниц (JPEG до 1600 px). Галочкой
  «Отправлять картинки страниц» можно оставить только текст — дешевле, подойдёт любая текстовая модель.
- Модель `auto` с картинками превращается в маршрут OmniRoute `auto/best-vision`, без картинок остаётся `auto`.
  Можно указать конкретную модель, например `openai/gpt-5.4`.
- Ответ модели проверяется теми же правилами, что и шаблоны: контрольная сумма ИНН, сходимость НДС,
  форматы БИК и счетов. Если ИИ ошибся в цифре ИНН, а шаблоны нашли корректный — берётся корректный.
  Пустые поля ИИ дополняются результатом шаблонов.
- OmniRoute не запущен, провайдер не ответил или вернул ерунду — документ всё равно распознаётся шаблонами,
  а в предупреждениях написано, почему без ИИ.
- Из командной строки: `Scan2-1C.exe --extract скан.pdf --ai --out r.json` (адрес и ключ — из настроек).

**Конфиденциальность:** с ИИ сканы уходят тому провайдеру, к которому OmniRoute направит запрос. Для документов,
которые нельзя отдавать наружу, подключите в OmniRoute локальную модель (например, через Ollama) или не включайте ИИ.
Ключ OmniRoute хранится зашифрованным, как и пароль 1С.

## Автообновление

При каждом запуске программа заходит в релизы GitHub этого репозитория и ищет версию новее своей
(релизы с тегом `scan2onec-v<версия>`). Если находит — сама скачивает её в фоне, ход загрузки виден
в строке состояния окна, работать при этом можно.

1. Скачанный файл проверяется: размер, контрольная сумма SHA-256, которую публикует GitHub,
   и то, что новая версия запускается (`Scan2-1C.exe --self-check`). Повреждённое обновление не ставится.
2. Затем новая версия встаёт на место старого exe. Путь к программе и ярлыки не меняются.
3. Если список документов пуст, программа сразу перезапускается в новой версии. Если вы уже работаете
   со сканами — спросит, перезапустить сейчас или новая версия откроется в следующий раз.

Выключить: «Настройки» → «Обновлять автоматически с GitHub». Там же кнопка «Проверить сейчас».
Если папка программы закрыта на запись (например, `C:\Program Files`), программа сообщит об этом —
перенесите exe в свою папку. Нет интернета или GitHub недоступен — программа просто работает дальше.

Версия 1.0.0 обновляться не умела: её один раз нужно заменить на новую вручную.

**Как выпустить обновление:** поднимите `__version__` в `scan_to_1c/__init__.py` и влейте изменения в `main`.
Сборка опубликует релиз `scan2onec-v<версия>`, и программы пользователей подтянут его при следующем запуске.
Без смены версии обновление до пользователей не дойдёт.

## Подготовка базы 1С для загрузки через OData

1. Опубликуйте базу на веб-сервере (IIS или Apache): Конфигуратор → Администрирование → Публикация на веб-сервере,
   галочка «Публиковать стандартный интерфейс OData».
2. В режиме 1С:Предприятие откройте «Настройку стандартного интерфейса OData»
   (в БП 3.0 — Администрирование → Синхронизация данных; в любой конфигурации — «Все функции» → Обработки)
   и включите в состав:
   `Справочник.Организации`, `Справочник.Контрагенты`, `Документ.ПоступлениеТоваровУслуг`.
3. Заведите пользователя 1С с правами на эти объекты. Адрес в настройках программы — адрес публикации,
   например `http://server/accounting` (часть `/odata/standard.odata` программа добавит сама).

Пароль хранится в `%APPDATA%\Scan2-1C\settings.json`, зашифрованный средствами Windows (DPAPI) —
прочитать его может только тот же пользователь Windows.

## Шаблон выгрузки: другие документы и конфигурации

По умолчанию создаётся «Поступление (акты, накладные, УПД)» 1С:Бухгалтерии 3.0 с заполненной шапкой:
организация, контрагент, входящий номер и дата, сумма, комментарий. Всё это — шаблон в «Настройках»,
его можно поменять под УТ, КА, ERP или другой документ без переделки программы:

```json
{
  "organization": {"entity": "Catalog_Организации", "inn_field": "ИНН", "default_key": ""},
  "counterparty": {
    "entity": "Catalog_Контрагенты", "inn_field": "ИНН", "kpp_field": "КПП", "create_if_missing": true,
    "fields": {"Description": "{seller_name}", "ИНН": "{seller_inn}", "КПП": "{seller_kpp}"}
  },
  "document": {
    "entity": "Document_ПоступлениеТоваровУслуг",
    "fields": {
      "Date": "{date}T00:00:00",
      "Организация_Key": "{organization_key}",
      "Контрагент_Key": "{counterparty_key}",
      "НомерВходящегоДокумента": "{number}",
      "ДатаВходящегоДокумента": "{date}T00:00:00",
      "СуммаДокумента": "{total}",
      "Комментарий": "Загружено из скана {file_name}"
    },
    "duplicate_check": ["НомерВходящегоДокумента", "Контрагент_Key"]
  }
}
```

- `"{поле}"` целиком заменяется значением с сохранением типа (число остаётся числом), внутри текста — подставляется строкой.
- Доступные поля: `doc_type`, `number`, `date`, `total`, `vat`, `vat_rate` (`20%`), `vat_rate_1c` (`НДС20`),
  `seller_name`, `seller_inn`, `seller_kpp`, `seller_legal_form`, `buyer_name`, `buyer_inn`, `buyer_kpp`,
  `bik`, `account`, `file_name`, `organization_key`, `counterparty_key`.
- Если в базе несколько организаций и ИНН покупателя на скане не распознаётся, впишите в `default_key`
  `Ref_Key` нужной организации.
- Табличную часть тоже можно заполнить, например одной строкой услуг:
  `"Услуги": [{"LineNumber": "1", "Содержание": "По документу {number}", "Количество": 1, "Цена": "{total}", "Сумма": "{total}", "СтавкаНДС": "{vat_rate_1c}", "СуммаНДС": "{vat}"}]`.
- Пустые значения не отправляются, поэтому нераспознанное поле не сломает загрузку ссылочного реквизита.

## Ограничения

- Табличная часть (строки товаров) из скана не извлекается: в 1С приходит шапка документа с суммой,
  строки заполняются вручную или шаблоном (см. выше).
- Качество зависит от скана: лучше всего 200–300 dpi, ровный лист, без сильного сжатия JPEG.
  Рукописный текст не распознаётся.
- Скан не прикрепляется к документу в 1С при загрузке через OData; в режиме папки обмена копия скана лежит рядом с JSON.

## Разработка

```
cd scan-to-1c
pip install -r requirements.txt pytest
python -m pytest tests        # для тестов OCR нужен установленный Tesseract с языком rus
python main.py                # запустить окно
```

Exe собирает workflow [`.github/workflows/scan-to-1c.yml`](../.github/workflows/scan-to-1c.yml) на Windows:
ставит Tesseract, прогоняет тесты, собирает PyInstaller'ом один файл, проверяет его на тестовом скане
и публикует релиз `scan2onec-v<версия>` (версия — в `scan_to_1c/__init__.py`).
